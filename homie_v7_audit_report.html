1. 执行摘要

NO-GO

当前 HOMIE+ 不应进入实机验收；v7 也不能视为已完成版本

最严重的问题不是调参，而是端到端语义断裂：训练与 MuJoCo 中的 waist_pitch 由环境直接执行，实机脚本却只把 pitch 命令写进策略观测， 最终仍把腰关节固定在默认位。策略被告知“前倾”，机器人实际被持续要求“直立”。

同时，HIMPPO 镜像增强把未执行的随机镜像 action 与原 transition 的 reward/next-state 配对，污染一半 rollout storage；域随机化、课程恢复、导出 metadata 与实机 fail-safe 也存在确定缺口。上述问题应先于继续比较 v7 reward recipe 处理。

2. 目标、边界与 v1–v7 状态

基础 HOMIE

目标是复现 OpenHomie 的下肢 walk / squat / stand：策略只输出腿部动作，上身以平滑随机目标作为外部扰动， 训练下肢在不同上身姿态、负载与物理扰动下维持运动和高度。

4. 核心发现

“事实”表示有明确代码链或运行实验；“风险”表示机制明确、但仍需 rollout/实机验证最终行为。严重度按目标阻断、训练污染、部署安全和影响范围评定。

Critical · 事实HOMIE+ 实机不执行 torso pitch，核心能力在 sim→real 处断裂F-01
训练环境TorsoPitchAction 将目标设为 default + pitch command，并做 slew。
策略 / ONNX第五维命令进入观测；网络只输出 12 条腿。
独立 runtime非策略关节全部复制 default，腰 pitch 没有重建。
实机 LowCmd29 维目标全写入；腰与手臂持续 held at default。

X/B 按键确实改变第 5 维观测，但 policy.act() 仅在 12 个 action joint 上叠加输出， 随后 write_all_joints() 把默认 waist_pitch 发给电机。因此这是确定的 command-to-actuator bug，不是策略表现不佳。

影响：策略观察到的任务与机器人实际约束相互矛盾；HOMIE+ 的弯腰/低位取物目标在当前实机入口不可实现。
为何 --sim 没抓到：仿真环境内部仍有零维 TorsoPitchAction，它替 runtime 直接驱动腰，正好掩盖实机缺口。

证据：mdp/actions.py:236–281 · runtime.py:165–181 · deploy_g1_homie.py:132–140, 190–200, 214–286

High · 事实镜像增强将未执行的随机 action 与原 reward / next-state 配对F-02

真实 transition 与合法镜像应为：

(s, a, r, s')  →  (M(s), M(a), r, M(s'))

当前实现却在 M(s) 上独立采样 a_sym ~ π(M(s))，随后复制真实 action a 产生的 reward 与 next-state：

(M(s), a_sym, r(a), M(s'(a)))

a_sym 从未在环境执行，PPO 的 log-prob、advantage、reward 与 dynamics 不属于同一条 transition。 transitions_per_step=2，所以这类样本占 storage 的 50%。末帧 GAE 还把原始 V(s_T) 广播给镜像 lane，而不是 V(M(s_T))。

v7 model_13600，4096 个零观测： mean_abs=0.6251，RMS=0.8027，max=3.9903， 与 M(a) 整条 allclose 的比例为 0；按 0.25 action scale，目标 RMS 错配约 0.2007 rad。
影响：这是训练数据一致性错误，影响所有启用 use_flip=True 的任务与既有 checkpoint。它从 OpenHomie 参考实现继承而来，但“上游相同”只能说明复现来源，不能使 transition 合法。

证据：algorithm.py:213–315 · storage.py:46–51, 145–166 · OpenHomie him_ppo.py:94–139

High · 事实上身课程无法从 checkpoint 恢复，且 30k run 没训练到全幅目标F-03

checkpoint 环境状态恢复了 common_step_counter，但 UpperBodyPoseAction._curriculum_ratio 是独立运行时 tensor，没有保存/恢复；resume 后必定回到 initial_ratio=0。历史日志中，原 run 约 step 6203 为 0.05，resume 在 step 6200 与 10079 均为 0。

即便 fresh training，最近完成的 v6 到 29,999 也只到 ratio 0.35，v7 在约 14k 时为 0.05；配置目标为 1.0。 OpenHomie 默认 100k iterations，而本仓库 runner 上限 30k。v6 末段 tracking success 仍低于 0.8 门槛，因此无法继续爬升。

影响：“对任意连续变化上身姿态鲁棒”是 HOMIE 的核心目标，但现有完成 run 没覆盖完整课程；resume 还会静默改变训练分布。
额外语义 bug：ratio=0 也不等于关闭运动。相同采样公式 100 万次蒙特卡洛：均值为关节范围的 2.50%，p99 15.2%，全部非零。 真实 G1 play 在 HOMIE_PLAY_UPPER_RATIO=0 下采样一次，15/15 上身 joint 目标非零，最大偏移 0.447 rad。 因此“play 默认 held at default”同样不成立。

证据：actions.py:109–201 · curriculums.py:15–62 · runner.py:119–150 · rl_cfg.py:61–69

High · 事实质量 DR 物理不一致，且 link scale 被 payload 事件覆盖F-04

link_mass 先对全身做 scale，payload_mass/hand_payload 后做 add。 mjlab 的 scale 与 add 都以 compile-time default 为 base，后执行的 add 会覆盖重叠 body 的前一次 scale，而非组合。 同时 dr.body_mass 明确只改质量、不改惯量；这不适合全身 density uncertainty，也与 OpenHomie 的 recomputeInertia=True 不对齐。

定值控制实验：torso 默认质量 7.818，先设 link ×2、再 payload +1； 正确组合应为 16.636，实际为 8.818（default +1）。三轴 inertia 与 default 完全相同。 另一实验中 torso/左右 wrist 的 mass ratio 精确回到 1.0，而不重叠的 knee 保留随机 ratio 0.878103。
影响：所有任务的 sim2real 惯性分布错误；torso/hand 重叠部位实际没有代码注释所称的 link uncertainty 与 payload 联合分布。

证据：homie_env_cfg.py:251–269 · env_cfgs.py:273–308, 746–815

High · 事实Encoder bias 没进入观测，注释所称的 calibration 模型并未实现F-05

actor/critic 使用原始 asset.data.joint_pos，position target 却减去 bias。 这更接近隐式 target/torque offset，而不是“传感器读数与 target 一致偏移”的编码器零点误差。

运行实证：bias_max=0.04863；观测与 raw q 最大差为 0，与 biased q 最大差为 0.04863。
影响：若目标是复刻 OpenHomie actuation injection，可以作为近似但应准确命名；若目标是 encoder robustness，则当前训练分布缺失。

证据：homie_env_cfg.py:230–239 · observations.py:59–66 · actions.py:76–79

High · 事实v1–v7 checkpoint 语义可静默错配，导出 provenance 记录的是错误时点F-06

v1–v7 共用同一 task ID 与 486 维 actor interface，但 command sampler、height step/slew、pitch 分布、slew range、奖励及 gate 多次改变。 当前 CLI 加载旧 v1–v6 checkpoint 时会直接实例化 v7 环境；shape 能通过，因此不会报错，却无法复现实验原语义。

checkpoint 本身没有训练 commit/recipe version。ONNX 的 train_repo_commit 又是在导出时读取当前 HEAD， 并非 checkpoint 的训练 commit；在 v7 HEAD 重导 v6，会被错误标成 v7。run 目录虽保存 params/env.yaml 与 git diff，可人工救援，但没有自动契约。

影响：旧策略可在错误 command/reward semantics 下被播放、比较或交付，实验结论和部署 provenance 不可信。

证据：exporter.py:118–142 · __init__.py:35–53

High · 事实H1-with_hands 导出 metadata 与网络真实 layout 冲突F-07

挂手模型有 37 个非 free joint，但 actor observation 只选固定的 19 个 H1_ALL_JOINTS。 exporter 正确算出单帧输入 58，却用 len(robot.joint_names)=37 描述 joint_pos/joint_vel，宣称单帧应为 94。 

真实：4 command + 6 IMU + 2×19 joint + 10 action = 58
metadata：4 + 6 + 2×37 + 10 = 94

base metadata 还出现 joint_names/default_pos=37，stiffness/damping=21；左右 Robotiq 内部 basename 重复，37 个名称仅 29 unique。 网络本体可正常导出为 348→10，但 metadata 无法安全驱动下游。

影响：该变体的自动导出产物不可作为可靠控制契约；canonical runtime 会因 layout 校验失败或名称歧义拒绝/误映射。

证据：env_cfgs.py:636–669, 766–803 · exporter.py:197–228

High · 安全实机循环缺少 stale-state watchdog、finite 检查与硬限幅F-08

当前 LowCmd 主循环没有以下保护：

  • LowState 时间戳/接收间隔 watchdog；
  • sensor、observation、ONNX output 的 isfinite 检查；
  • policy action 与最终 joint target 的 hard limit / delta limit；
  • 连续 loop overrun 或 inference timeout 保护。

DDS 状态冻结时，遥控器 SELECT 也冻结，循环仍会基于旧状态持续发送新命令；NaN/极端输出会直接写入 mc.q。 reward 中的软 penalty 不能替代部署边界检查。

影响：这是独立于策略质量的实机安全阻断项。首次上机即使有吊架，也不应省略软件失效保护。

证据：deploy_g1_homie.py:115–205 · runtime.py:165–181

High · 对齐G1-native 不是其注释承诺的完整 OpenHomie parityF-09

native 被注册注释称为 frozen parity 与“authoritative deviation ledger”，但该分支只回退 torso payload、hand payload 与 hip/knee reward。 当前物理自碰撞仍启用；OpenHomie 的 G1 则禁用 self collision。代码自身记录默认姿态腕—髋 contact 约占 25–30% steps，删除 reward 并不会删除动力学接触。

另外仍有 deploy gain、29 vs 27 DOF observation、reset/link-mass/action-delay、MuJoCo contact model 等行为差异。 其中 action delay 在参考实现中虽计算 delayed action，但物理 loop 使用的仍是当前 action；本仓库 delay 实际生效。

影响：native 最多可称“配置意图接近参考”，不能作为 executable parity 或三项权威差异清单。

证据：__init__.py:23–33 · env_cfgs.py:488–496, 616–622

Medium · 事实HOMIE+ --sim 的 bit-for-bit 检查固定假失败F-11

pin() 写 height.height_command，却不同步私有 _height_target。环境每步先向旧 target slew 并生成 observation，脚本随后才再次 pin。 v6/v7 所有 phase 因此稳定出现 obs_max_diff=8.61e-3，远高于 1e-4 阈值；而直接 ONNX/PyTorch 对齐在 1e-6 量级。

证据：deploy_g1_homie.py:227–286 · velocity_command.py:224–283

Medium · 事实其他确定契约/时序缺口F-12
  • mjlab_gains runtime：metadata 将逐关节 action scale 导出为 12 元 CSV，runtime 却调用 float(...)，确定抛 ValueError。
  • push/reset 顺序：global push 每 4 s，episode 20 s；timeout 同步时 mjlab 先 reset 后 interval push，初始 vx∈[-.5,.5] 再叠加 [-.5,.5]，定值实验得到 raw qvel=1.0。参考实现中 reset 会覆盖该 push。
  • legacy checkpoint：带 critic 的训练 runner 经上游 loader 处理旧 model_state_dict 后，HIMPPO 可能静默不读迁移出的 policy keys；actor-only play fallback 不受影响。
  • command metrics：每步误差除以 4 s window steps，但只在 20 s episode reset 清零，因此日志约为 5×时间均值且随早停长度改变；名称“error”容易误读。
  • play 不是 nominal：仍保留 friction U(0.1,3.0)、mass/COM/encoder、PD-gain DR 与随机 reset；同时保留大量 reward-only contact sensors。

5. 奖励、命令与变体特有风险

v7 的动机合理：针对 kneeling、sumo squat 与 toe-crouch 逐步加约束。但当前组合存在确定的 gate 不连续、覆盖空窗与未条件化先验；以下区分“代码确定”与“行为待验证”。

项目当前机制判断严重度
Orientation ↔ pose priorh<0.775 时 orientation 立即从 1.0 降为 0.3；pose prior 到 h≥0.62 已完全为 0；hip/ankle deviation 同时关闭。[0.62,0.775) 是明确的姿态约束空窗，下降 5 mm 即发生 70% 离散降权。应使用同一平滑区间交接。High risk
Pose prior 与 pitch腿部 reference 由固定 waist_pitch=0.25 扫描拟合；实际 command 为 [-0.2,0.45]。不同 torso pitch 下同一腿部参考不一定 CoM 平衡；宜用 (height,pitch) 二维先验。机制风险明确，最终影响需 A/B。Medium
Feet load asymmetry奖励 |F_l-F_r|/(F_l+F_r)，只按 in-place command 范数 gate，不含方向/相位。可作为探索 bridge，但静态单侧压重也能持续收奖；需核对是否真正转化为转身/侧移。Medium
In-place sampler只把 vx=0，对 vy/wz 的 dominant axis 做最小幅值 clamp；另一轴连续采样。精确 pure turn（vy=0）和 pure strafe（wz=0）概率仍为零，注释与测试声称的 exact corner 不成立。Medium

H1：存在未定价的坐地/躯干触地解

G1 有 pelvis/torso-ground termination；H1 sensors 只有 feet、self、hip/knee，后者又排除 pelvis/torso。 H1 深蹲目标最低 0.40 m，策略可保持 pelvis 近直立并让 pelvis/torso 接地，不触发 fell-over 或 hip/knee penalty。 再叠加 step height、squat 时 stand-still/too-wide gate 关闭，这是高风险局部最优，需固定 h=0.4 contact probe。

H1-with_hands：不可观测 joint 进入 reward

actor/critic 只观察 19 个 H1 joint；新增 18 个 wrist/gripper joint 由被动动力学或 policy-free gripper goal 驱动。 但 dof_acc 与 joint_power 默认统计全部 joint，使下肢策略因不可观测、不可直接控制的手部运动被扣分。 强制闭合实验中额外 joint 贡献约 3.6% acc cost 与 0.35% power cost，属于 POMDP reward noise。

H1-with_hands：资产接线待澄清

左右 wrist hinge 不在 H1 observation、upper action 或 gripper actuator action 中，实测会被动漂移；若预期自由腕，应文档化，若预期 PD hold，则是漏接。 mounting helper 还把 wrist body 与新 hand site 重复施加同一平移，site 比实际腕端多偏约 0.28 m；当前任务未使用该 site，但属于潜在资产 API bug。
